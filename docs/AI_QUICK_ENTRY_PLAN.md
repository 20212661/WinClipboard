# WinClipboard 快速 AI 入口设计草案

日期：2026-10-13。状态：用户已选择“轮盘选动作＋AI 结果浮窗”；第一阶段已实现，第二阶段的全局按住键拖动尚未实现。

## 1. 调研结论

最匹配的项目是 [darrenprx/lolPing](https://github.com/darrenprx/lolPing)。它提供桌面轮盘：按住触发键拖动选择，松开执行；中心、右键或 Esc 取消。实现使用独立 C++ 输入助手和 Electron 覆盖层。[项目中文说明](https://github.com/darrenprx/lolPing/blob/main/README.zh-CN.md)

其 [Issue #39](https://github.com/darrenprx/lolPing/issues/39) 正在讨论用问号唤起 AI；作者提到考虑做成可选插件。该讨论不能当作已经交付的 AI 功能。

可借鉴的是鼠标附近的快速动作选择和退出规则。WinClipboard 可继续使用 PySide6 和现有 Windows 适配层。若要实现原版全局按键＋拖动，需要新增输入状态机，现有 RegisterHotKey 不能独自实现全局鼠标手势。[输入设计](https://github.com/darrenprx/lolPing/blob/main/docs/design.md)

## 2. 目标体验

主路径：**复制内容 → 快速唤出 → 选择 AI 动作 → 就地查看回答 → 复制或明确点击回贴**。

用户不必打开主窗口、创建工作流、输入同一条指令或切换到其他聊天软件。输入材料与当前应用场景保持关联，入口与结果页分别负责选择动作和阅读/追问。

## 3. 暂定入口

推荐“轮盘选择动作＋AI 结果浮窗”；同一功能服务也可支持快捷键直接打开输入面板。

第一阶段使用可配置组合热键，在鼠标附近显示轮盘。窗口打开后可鼠标点击、拖动松开或键盘选择，中心和 Esc 取消。这样先完成业务闭环。

第二阶段再增加全局按住侧键/修饰键拖动的手势触发，保持无需切换工作窗口的体验。需要单独处理输入透传、抬键配对、全屏暂停、窗口权限、多屏/DPI 和异常释放。不要默认拦截普通 Ctrl＋拖动，以免影响选字与文件操作。

## 4. 第一版动作

| 动作 | 输入 | 输出 |
|---|---|---|
| 解释 | 复制的文字、概念、代码或报错 | 通俗解释，代码/报错按内容给原因和建议 |
| 翻译 | 当前复制文本 | 可配置目标语言；默认中英互译 |
| 总结 | 文章片段、会议记录等 | 要点和简短摘要 |
| 润色 | 草稿、邮件或段落 | 保留原意的改写，可选择语气 |
| 自定义提问 | 剪贴板内容＋用户问题 | 带材料的回答 |
| 带资料提问 | 剪贴板内容＋显式选择的上下文包 | 基于多个资料片段回答 |

轮盘动作应允许后续配置名称、提示词和默认服务，避免首版出现多层菜单。代码修复可以先作为解释/自定义动作的模板，再根据使用频率决定是否独占扇区。

## 5. 输入规则

- 默认读取**触发时系统剪贴板的文本快照**，而不是历史列表第一条，防止暂停记录、排除应用或敏感隔离时使用了旧内容。
- 在历史卡片或快捷浮层触发时，以用户明确选中的记录为输入。
- 默认只附加本次材料；上下文包须有明确的选择状态，不自动发送整个历史或全部私密区。
- 空文本显示提示并允许直接提问；读取失败有重试入口，不能悄悄发送上一条缓存。
- 首版处理文本。截图 OCR/视觉解释作为后续能力，需要多模态服务配置和真正的图片请求格式；已有 image_ref 不等于图片附件。
- 文件列表只是路径，不代表已经读取文件正文；读取文件内容应有单独、可见的操作。
- 选中文字免复制可在后续增加，必须处理模拟复制的权限、失败、剪贴板恢复和自捕获，不承诺所有应用均支持。

## 6. 结果浮窗

鼠标所在屏幕内展示可调整大小的浮窗：输入摘要、当前动作、模型、回答，以及“复制”“粘贴回原窗口”“存入历史”“加入上下文包”。可输入追问、停止、重试、固定窗口。

初版复用现有后台请求可一次显示完整回答；若目标包含快速首字体验，应增加流式 API 调用和分段刷新，不能仅以窗口弹出快来宣称 AI 响应快。会话需显式限制上下文长度并显示附带资料范围。

触发时保存来源窗口句柄。回贴仅发生在用户明确点击后，继续使用目标窗口与剪贴板序列号保护；来源窗口已失效时保留可复制结果并解释原因。生成期间不自动覆盖剪贴板。

## 7. 复用与新增

| 能力 | 当前接入点 | 工作 |
|---|---|---|
| AI 服务和模型 | config.ai_services、clipboard_manager.ai_chat | 复用；快捷入口支持选择服务 |
| 发送前隐私扫描 | privacy_scan、PrivacyGateDialog | 复用；构造完整 prompt 后扫描 |
| 上下文拼装 | ctxpack.assemble | 复用预算和提示，但先修复模板二次替换等相关问题 |
| 后台请求 | workflow_ui.AIWorker | 初版复用；先统一取消与线程生命周期 |
| 复制/回贴 | ClipboardCore.copy_text/paste_text | 复用失败反馈和目标保护 |
| 新入口 | 新 ai_quick 包 | 轮盘、动作模型、协调器、结果浮窗 |
| 热键 | win32_host.TrayWorker | 新事件及注册/冲突反馈 |
| 手势输入 | 后续独立适配模块 | 单独状态机，输入路径不执行网络或复杂 UI 工作 |

建议新代码以 QuickAIRequest（动作、输入快照、来源窗口、服务、可选包）、QuickAIController（发送与取消）、QuickAIWindow（呈现）分离，避免继续把全部逻辑堆进主窗口文件。

## 8. 需要先处理的关联问题

快速入口可以独立推进，但应先确保所有新测试在导入前隔离 APPDATA；发送模板一次替换；在慢响应、取消、关闭窗口和主应用退出时，所有 AI 线程有明确持有者和回收路径。

当前审计中的安全模式、导入持久化等问题仍需修复，新增入口不能被描述为已解决这些问题。新版本完成后要重新构建，与现有旧 EXE 区分。

## 9. 验收标准

1. 任意普通应用复制文字后，无需打开主窗口即可触发并完成解释/翻译。
2. 触发时冻结输入；请求过程中其他复制行为不会改变本次材料。
3. 内容、动作与目标服务可见；敏感扫描取消后无网络请求。
4. 调用失败可重试；结果未生成前不自动覆盖剪贴板；回贴失败有明确反馈。
5. 取消、重复触发、慢响应、窗口关闭和退出不发生线程析构崩溃或迟到结果串入新请求。
6. 轮盘在屏幕边缘、多屏和高 DPI 下保持可操作；Esc 不误发请求。
7. 热键冲突能提示并更换；后续手势开启时普通复制、拖动、侧键点击和全屏交互仍有明确规则。
8. 离屏测试后补真实桌面验收，覆盖触发、来源窗口保持、结果复制/回贴和退出。

## 10. 当前使用方式

源码运行时，先在「AI 服务」页配置服务，然后复制文本并按 **Ctrl＋Alt＋空格**。轮盘支持鼠标选择和数字 1–6，中心、右键或 Esc 取消。历史文本卡片右键也有“快速 AI…”；设置页提供打开按钮和热键录制，热键冲突保留原组合。

轮盘动作有解释、翻译、总结、润色、自定义提问、带资料提问。前四项在已有服务和文本时直接发送，后两项先填写问题。结果浮窗支持复制、明确点击回贴、存入历史、加入包、停止等待和重新发送；Ctrl＋Enter 发送，Esc 隐藏。附加包使用活动上下文包，缺失或不可拼装则拒绝发送。

新增实现文件 `ai_quick.py`；新增回归 `_quick_ai_test.py`；统一检查已登记 quick-ai 和原先漏登记的三组 ctxpack 测试，并在每个子进程导入前隔离 APPDATA/TEMP/TMP。输出当前为一次性完整回答，停止只丢弃迟到结果，不撤回已送往服务商的请求；最多两条请求同时在途。

验证材料：`docs/ui/quick_ai/` 内有深浅色轮盘与回答浮窗截图；`_integration_sandbox_test.py` 为系统剪贴板和原生 worker 使用替身的界面/核心集成验收，不能替代真实复制和回贴验收。`docs/quick_ai_preview.py` 启动独立数据目录的真实桌面预览，禁用后台捕获；已通过 WM_HOTKEY(105) 验证唤出轮盘。没有调用真实模型，现有 EXE 没有重建。
